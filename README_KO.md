# DeruyPlugin 1.1.0 — 운영 기능 8가지 보완

## 설치와 버전

이 소스의 기존 빌드 대상인 **Paper 1.21.11 / Java 21**을 유지했습니다.
Paper 26.2용 호환성 변경을 적용한 버전은 아닙니다.

1. 서버를 종료하고 기존 플러그인 JAR와 `plugins/DeruyPlugin/`을 백업합니다.
2. 압축 안의 `DeruyPlugin-1.1.0.jar`를 서버 `plugins/`에 넣고 기존 DeruyPlugin JAR를 제거합니다.
3. 기존 `config.yml`과 `data.yml`은 유지하고 서버를 시작합니다.
4. 아래 새 설정을 기존 config의 해당 섹션에 추가하면 직접 바꿀 수 있습니다. 항목을 생략하면 기본값이 적용됩니다.

`src/main/resources/config.yml`은 전체 설정 예시입니다. 기존 config 전체를 덮어쓸 필요는 없습니다.

## 1. 전투 중 로그아웃

기존 `combat-tag` 섹션에 추가:

```yaml
combat-tag:
  duration-seconds: 15
  logout-penalty: CHAT
```

| 값 | 동작 |
| --- | --- |
| `CHAT` | 전투 중 로그아웃했다는 채팅 알림만 표시 (기본값) |
| `KILL` | 로그아웃 시 사망 처리. 자연사 차감이 꺼져 있어도 하트 차감 |
| `NONE` | 채팅 알림과 사망 처리 없음 |

KILL은 자발적인 종료와 네트워크 끊김을 구분하지 않습니다. 서버 종료 중에는 페널티를 적용하지 않습니다.
사망했거나 전투 태그가 만료된 플레이어에게는 적용하지 않습니다.
마지막 상대가 온라인이면 해당 상대를 킬 보상 대상에 사용할 수 있으며, 기존 역할별 손실 배수와 상한 초과 하트 드롭 규칙을 따릅니다.
`messages.combat-logout`에 `{player}`를 넣어 방송 문구를 바꿀 수 있습니다.

## 2. 전투 태그 판정

직접 공격과 플레이어가 발사한 투사체(화살·삼지창 등)에 적용합니다.
취소된 공격, 최종 피해 0, 자신에게 맞힌 투사체에는 태그를 부여하지 않습니다.
피해 처리가 끝나는 MONITOR 단계에서 양쪽 전투 태그를 갱신합니다.
사망·로그아웃 시 해당 플레이어의 태그를 정리합니다.

## 3. /heart 관리자 명령어

권한: `deruy.heart.admin` (기본 OP).

| 명령어 | 동작 |
| --- | --- |
| `/heart info <플레이어>` | 현재 하트·상한·밴 기준 조회 |
| `/heart set <플레이어> <하트>` | 하트 직접 설정 |
| `/heart add <플레이어> <하트>` | 역할 상한까지 추가 |
| `/heart remove <플레이어> <하트>` | 차감. 최소 하트 이하가 되면 밴 |
| `/heart revive <이름 또는 UUID> [하트]` | LifeSteal 밴 해제 및 하트 복구 |

info/set/add/remove는 온라인 플레이어 대상입니다.
revive는 접속 기록이 있는 오프라인 플레이어도 지원합니다. 다음 접속 때 적용할 하트를 data.yml에 저장하며, 실제 접속 시 역할 상한을 반영합니다.
다른 출처의 밴은 이 명령어로 해제하지 않습니다. 기존 버전의 `LifeSteal` 출처 밴도 지원합니다.
set은 밴 기준보다 높은 값만 허용합니다. add는 상한에서 잘라 적용하고 실제 변경량을 기록합니다.
현재 기본 설정은 **5하트 이하 도달 시 밴**이므로 set·부활·인출 후 잔여 하트는 5보다 높아야 합니다.

```yaml
heart:
  revive-hearts: 10
  audit-enabled: true
```

## 4. 하트 변경 기록

`plugins/DeruyPlugin/logs/hearts-YYYY-MM-DD.tsv`에 UTC 날짜 기준으로 기록합니다.
시간 / UUID / 이름 / 변경 전 하트 / 변경 후 하트 / 사유 순서입니다.
킬, 사망, 전투 로그아웃, 하트 아이템, 인출, 관리자 변경, 부활 예약·적용을 구분합니다.
부활 예약 행의 변경 전 값 `-1`은 오프라인 현재 하트를 읽지 않았음을 뜻합니다.
파일 기록은 순서가 유지되는 별도 작업 스레드에서 수행합니다. 다른 플러그인이 직접 변경한 체력은 이 로그의 대상이 아닙니다.

## 5. 제한 아이템 제작

Shift 클릭도 한 개씩 상한을 확인하고, 각각 다른 UUID를 발급합니다.
인벤토리 보관 칸이 부족하면 재료를 소비하지 않습니다. 일반 클릭은 비어 있는 커서에 한 개씩 지급합니다.
숫자키 교환·드롭 클릭 등 우회 입력은 추적 대상 제작에서 차단합니다.
자동 제작기(CRAFTER)는 `item-limits`에 등록된 조합법을 제작할 수 없습니다. `00`으로 무제한을 지정해도 등록된 조합법은 추적 대상입니다.
파괴·내구도 소진 외에 추적 토템의 발동도 개수에서 차감합니다.
기존 버전이 이미 만든 UUID 중복·유실을 자동으로 전수 복구하는 기능은 아닙니다.

## 6. 설정 검증과 리로드

`/deruyreload`는 YAML과 주요 설정값을 먼저 검사합니다. 잘못된 값이면 기존 실행 설정을 유지하고 오류 경로를 채팅에 표시합니다.
하트 범위·역할 상한·시간·빙고 크기·피치·보급 개수·보상 확률·조합법 재료/모양 등을 확인합니다.
레시피, LifeSteal·음성·KOTH의 메모리 상태, 경계 표시, 로케이터, 보급 자동 실행 상태도 다시 적용합니다.

- 레시피 변경도 재시작 없이 반영됩니다.
- 보급 생성 예약은 취소되고 일반 보급의 당일 랜덤 일정은 다시 계산됩니다.
- 빙고 크기나 제외 목록을 바꾸면 진행 중인 빙고판을 새로 만듭니다. 그 외에는 진행도를 유지합니다.
- 이미 생성된 보급상자는 유지됩니다.
- 현실 시간은 서버 JVM의 시간대 기준입니다. `/deruytime`으로 확인하세요.

## 7. 보급상자 보호와 예약 취소

기존 `supplydrop` 바로 아래, normal/super와 같은 들여쓰기 단계에 추가:

```yaml
supplydrop:
  chest-destruction: PROTECT
  # 기존 normal: ... 과 super: ... 유지
```

| 값 | 동작 |
| --- | --- |
| `PROTECT` | 플레이어 파괴·폭발로부터 보호. 우클릭으로 수령 (기본값) |
| `DROP` | 파괴·폭발 시 보상을 바닥에 떨어뜨리고 저장 데이터 제거 |

호퍼 입출력과 보급상자 인벤토리 열기는 차단합니다. 상자를 붙여 이중 상자로 만드는 것도 차단합니다.
보상은 우클릭 시 지급되는 기존 방식을 유지합니다.
`/supplydrop stop`, `/supersupplydrop stop`은 자동 체크와 아직 생성되지 않은 상자 예약을 모두 취소합니다.
자동 실행을 켜지 않은 상태에서 force만 사용했어도 stop으로 예약을 취소할 수 있습니다.
이미 생성된 상자와 내용물은 data.yml에 남아 재시작 후에도 수령할 수 있습니다.
로드된 청크에서 실제 상자가 사라진 기록은 정리하며, 그 안의 제한 아이템 추적도 해제합니다.
상자 위치를 강제로 지우는 외부 플러그인·관리 명령을 전부 실시간으로 감지하는 것은 아닙니다.
빈 위치가 아니거나 인접 상자가 있는 생성 후보는 건너뛰므로 실제 생성 수는 설정 수보다 적을 수 있습니다.

## 추가 기능 (2026-11-23)

### 하트 운송전 수레
- 리소스팩 `resourcepack/DERUY_TreasureWagon` 필요 (1.21.11). 몸체 1개 + 바퀴 4개 디스플레이.
- **손상 단계**: 남은 체력 75% / 50% / 25% 이하가 되면 모델이 부서진 모습으로 바뀜 (`transport-model.yml` → `damage-stages`). 25%는 앞왼쪽 바퀴가 빠지고 기울어짐.
- **보물 흘림**: 단계가 나빠질 때마다 남은 보물 중 `spill-per-stage`(기본 15%)를 바닥에 쏟음. 쏟은 만큼 파괴 드롭이 줄어듦. 줍기 권한은 파괴 드롭과 같음 (`transport-game.yml`).
- **움직임**: 바퀴가 굴러간 거리만큼 돌고, 몸체가 단계별로 더 흔들림 (`motion.wobble-degrees`). 바퀴가 거꾸로 돌면 `motion.spin-direction: -1`.
- 리소스팩 없는 서버는 `transport-model-blocks.yml` 내용으로 바꾸고 `/transport reload`.

- 추첨 중(노란색) / 진행 중 이벤트 이름 + 남은 시간(빨간색). `random-events.bossbar: false` 로 끔.

### 영상 편집용 타임라인

- 종류: `KILL` `DEATH` `HEART` `RANDOM_EVENT_START/END` `KOTH_START/CAPTURE/END` `BOUNTY_KILL` `SUPPLY_DROP` `TRANSPORT_START/DAMAGE/DESTROYED/ARRIVED`
- `/deruy timeline [YYYY-MM-DD]` 으로 건수·파일 위치 확인. `timeline.enabled: false` 로 끔.
- 녹화 시작 시각과 비교하면 하이라이트 위치를 바로 찾을 수 있음.

## 서버 녹화 하이라이트 (Flashback)

클라이언트에서 녹화를 켜지 않아도 **서버가 접속자 전원을 녹화**해 두었다가, 장면이 나오면 그 부분만 Flashback 리플레이로 저장한다.

| 상황 | 저장 범위 |
|---|---|
| 플레이어끼리 때림 (활·삼지창 포함) | 첫 타격 **60초 전**부터, 마지막 타격 뒤 15초 동안 아무도 안 때릴 때까지 (+5초) |
| 랜덤 이벤트 | 이벤트 동안 접속자 전원 |
| 하트 운송전 / KOTH / 보급 | 열차·구역·상자 근처(64/48/32칸)에 들어온 사람, 이벤트 동안 |
| 퇴장 / 서버 종료 | 녹화 중이던 사람은 그때까지 저장 |

- 싸움·이벤트가 동시에 여러 개 나도 **플레이어마다 따로** 저장되고, 한 사람에게 겹치면 한 파일로 합친다(이름에 `pvp+randomevent` 처럼).
- 15분이 넘으면 파일을 나눠 이어서 저장(`_cont`).
- 첫 타격·처치·사망·보물 손상·점령·이벤트 시작/끝은 **마커**로 들어가 Flashback 타임라인에서 바로 이동할 수 있다.
- 파일: `plugins/DeruyPlugin/replays/<날짜>/<시각>_<종류>_<플레이어>.zip` → PC의 `.minecraft/flashback/replays/` 에 넣고 Flashback(1.21.11)에서 열기.
- 그 플레이어 **시점에서 보인 범위**(시야 거리 안)가 들어가고, 카메라는 Flashback에서 자유롭게 움직일 수 있다.

명령 (`deruy.admin`):

| 명령 | 설명 |
|---|---|
| `/deruy replay` | 녹화 상태(녹화 중인 사람·메모리·마지막 저장) |
| `/deruy replay list` | 최근 저장 10개 |
| `/deruy replay save [플레이어]` | 그 사람의 최근 1분을 지금 바로 저장 |
| `/deruy replay verify <파일>` | 저장 파일을 끝까지 읽고 모든 패킷을 서버 코덱으로 풀어 보는 검사 |

설정: `config.yml` 의 `replay:` (켜기/끄기, 시간, 반경, 메모리·디스크 상한). 녹화에는 채팅·귓속말(그 사람이 받은 것)도 들어가므로 서버원에게 알리고 폴더 접근을 관리할 것.
### 2차 (1.7.0): 전투 태그·카메라·킬캠·추적·편집 묶음

| 기능 | 설명 |
|---|---|
| 전투 태그 기준 | `replay.pvp.trigger: hit / combat-tag / both(기본)` — 라이프스틸 전투 태그가 붙은 동안 계속 녹화 |
| 고정 카메라(CCTV) | `/camera <이벤트> <이름> [반경]` 지금 자리·방향 저장 → 그 이벤트가 열리면 사람이 없어도 녹화. 한 이벤트에 여러 대 가능 |
| 킬캠 | 플레이어에게 죽으면 죽은 사람·죽인 사람 시점으로 마지막 15초(+3초) 짧은 파일 따로 (연달아 죽이면 하나로) |
| 추적 카메라 | 하트 운송전 열차·엔더 드래곤을 따라가며 녹화 (드래곤은 플레이어가 때리면 시작, 2분 조용하거나 죽으면 끝) |
| 편집용 묶음 | 리플레이 옆에 Resolve 마커 `.edl`(영상으로 처음부터 내보냈을 때 맞음, `replay.edl-fps`), 날짜 폴더에 `index.csv`·그날 `timeline.csv` |

카메라 명령 (`deruy.admin`):

| 명령 | 설명 |
|---|---|
| `/camera <koth·transport·randomevent·supply·dragon·always> <이름> [반경]` | 지금 서 있는 자리·보는 방향으로 카메라 등록 (always = 항상 녹화) |
| `/camera list` · `remove <이름>` · `tp <이름>` | 목록 · 삭제 · 그 자리로 이동 |
| `/camera test <이름> [초]` | 이벤트 없이 바로 시험 녹화 |

카메라 파일도 같은 리플레이 형식이라 Flashback에서 자유롭게 돌아다니며 볼 수 있다(첫 화면이 카메라 자리).
소리·파편·폭발 효과는 근처 플레이어가 받은 것을 나눠 받는다(1.7.1~). 그래서 플레이어 녹화에도 본인 발소리·휘두르기 소리가 근처에 다른 사람이 있으면 들어간다.

카메라는 1.8.0부터 자리에 **보이지 않는 관전자**(`~ear_카메라이름`)를 하나 둬서, 근처에 아무도 없어도 서버가 보내는 소리를 그대로 받는다(`replay.camera-ear`). 관전자는 접속 없이 서버 안에만 있고, 관전자 모드·몹 스폰 영향 없음·잠자기 인원 제외·탭 목록과 접속 메시지에서 숨김·이 플러그인 기능(이벤트 추첨, 보스바 등)에서 제외된다. 월드 규칙 `spectatorsGenerateChunks` 를 false 로 바꿔 관전자가 새 지형을 만들지 않게 한다(실제 관전자에게도 적용됨). `/list` 인원과 다른 플러그인에는 플레이어로 보일 수 있다. 카메라가 멈추면 관전자도 빠지고 데이터 파일은 지운다.

마인크래프트 1.21.11 전용(서버 내부 구조 사용). 버전이 다르면 이 기능만 꺼지고 나머지는 그대로 동작한다.

## 빌드와 검증

Java 21 + Maven에서 프로젝트 폴더 안에서 (처음 한 번 `tools/install-paper-dev.sh` — 서버 녹화 컴파일용):

```text
tools/install-paper-dev.sh
mvn clean verify
```

빌드 결과: `target/DeruyPlugin-1.1.0.jar`.
JUnit/MockBukkit 테스트로 설정 검증, 전투 태그, 하트 증감, 로그아웃 모드, 제작 상한과 빈칸 처리, 조회 권한, 예약 취소, 데이터 유지 등을 검증합니다.
MockBukkit에 없는 다이아몬드 조합 잔여물·서버 종료 상태 API만 테스트에서 대체합니다.
실제 운영 서버에서 여러 플러그인과 함께 동작하는 환경 테스트는 별도로 필요합니다.
